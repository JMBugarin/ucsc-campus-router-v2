# data/

The campus data the app ships. After changing a file here, run `scripts/sync_app_data.sh`: it copies `buildings.json`, `rooms.json`, `search_aliases.json` and `holidays.json` into `app/assets/data/`, and a test fails if the copies differ.

- `building_sources.json` — hand-edited. One entry per building: `id`, display `name`, `osm_name` (exact OpenStreetMap name), `facility_ids` (links the building to rooms in `classrooms.json`), and `aliases` (extra names; the official schedule names are added automatically). `osm_name: null` means no location is known yet.
- `classrooms.json` — generated by `data-pipeline/fetch_classrooms.py` from https://classrooms.ucsc.edu/ (each room's official schedule name, "AIS Display Name", and facility id) and the public classroom-points layer behind https://maps.ucsc.edu/ (each room's lat/lon and level). The fetcher waits as long as the site's `robots.txt` asks.
- `buildings.json` — generated by `data-pipeline/build_buildings.py`. Adds `centroid` and `entrances` from OpenStreetMap. Do not hand-edit; change the sources file and regenerate.
- `search_aliases.json` — extra names the search accepts, by building id (for example `BE`).
- `holidays.json` — each term's first and last day and its no-class days, from the registrar's calendar. Add the next term by hand.
- `rooms.json` — optional per-room overrides, keyed `"<building-id>:<ROOM>"`. An `entrance` here is the door **Walk there** uses for that room:

  ```json
  {"overrides": {"baskin-engineering:152": {"entrance": {"lat": 37.0, "lon": -122.06}, "floor": "1", "note": "use the north door"}}}
  ```
